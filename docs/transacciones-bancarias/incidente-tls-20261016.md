# Diagnóstico de conexión y opción explícita sin TLS

El 16/10/2026 se reprodujo el fallo con la configuración guardada en desarrollo, leyendo explícitamente `.env.development`. DNS, descifrado y política de destinos funcionaban. El conector devolvió `ER_SERVER_SSL_DISABLED`, errno 45023, SQLSTATE 08S01: el servidor no ofrece TLS. El diagnóstico anterior no incluía ese código del conector MariaDB y mostraba un mensaje genérico. El acceso desde otro cliente no acreditaba negociación TLS.

Se agregó ese error al catálogo de mensajes accionables junto con incompatibilidad TLS, identidad TLS, timeout de socket y cierre inesperado. Se examinan causas anidadas conocidas, con profundidad limitada y protección contra ciclos, sin publicar mensajes SQL/driver ni credenciales. Un servidor sin TLS nunca provoca un reintento automático sin cifrado.

El usuario eligió expresamente permitir una opción por conexión sin TLS, aceptando que contraseña y datos podrían viajar sin cifrar. Se agregó `configuracion_bbdd.tls_habilitado`, TINYINT NOT NULL DEFAULT 1, CHECK 0/1 y comentario detallado. La aplicación conserva TLS en todos los registros existentes hasta una edición explícita; el mismo valor es utilizado por el diagnóstico y por el consumidor bancario. Se aplicó mediante revisión y huellas del [manifiesto](../../scripts/database/plans/20261016-configuracion-bbdd-tls.json), seguido de `prisma-sync` sobre el mismo destino. No se cambió directamente la modalidad de la conexión guardada.

En Config BBDD, editar la conexión y desactivar **Usar TLS (recomendado)**. La pantalla muestra advertencia y deshabilita la referencia CA mientras TLS está apagado, conservándola para una futura reactivación. Probar utiliza el borrador actual; guardar persiste la decisión con control de versión. La lista identifica **SIN TLS**. El diagnóstico usa el nombre de etapa TCP/autenticación sin TLS y devuelve éxito con advertencia cuando corresponde. El cifrado GCM del secreto almacenado, la autorización de destinos y los controles SELECT del consumidor bancario permanecen activos.

Prueba real autorizada sin TLS con las credenciales almacenadas, sin mostrar secretos ni consultar movimientos: conexión exitosa a MariaDB 10.4.19, 11 bases visibles y acceso exitoso a la base configurada. `SHOW SESSION STATUS LIKE 'Ssl_cipher'` confirmó que la sesión no utilizaba TLS. Se cerraron las conexiones; no hubo escrituras locales ni remotas de datos para la reproducción. El script temporal de diagnóstico fue retirado; no se almacenaron los logs ni los tiempos de la prueba de conexión.

Validación: 43 pruebas backend aprobadas en diagnóstico, persistencia simulada de la bandera, permisos HTTP y lector bancario; 12 pruebas de interfaz aprobadas, incluyendo defecto TLS activo, desactivación explícita, advertencia, prueba y guardado sin reenviar contraseña. Tipos de aplicación/Vitest/integración del backend y aplicación/pruebas del frontend aprobados. ESLint focalizado aprobado. Son evidencias separadas de la prueba remota real; no se ejecutó la integración MariaDB desechable ni una suite completa como parte de este ajuste.
